# 文档处理流水线重构设计

## 1. 重构动机

### 1.1 当前问题

**两套流程代码重复、状态转换散落四处：**

- **流程一（用户上传）**：`POST /create` → `process_document` → 人工审核 → `vectorize_document`
- **流程二（文件夹监听）**：扫描 → `_ingest_one` → `process_document` → `_auto_process`（硬编码自动审核）

**具体问题：**

| 问题 | 影响 |
|------|------|
| `document_pipeline.py` 537 行，含 ~100 行死代码 | 维护困难，新人不理解 |
| `handle_bot_message` 塞在 Pipeline 里 | 职责混乱，与文档处理无关 |
| 状态跳转散落在 `reviews.py`、`feishu_folder_scan.py`、`documents.py` | 改了状态忘了触发下一步的风险 |
| `_auto_process` 在扫描服务里硬编码 APPROVED → vectorize | Pipeline 不知道 auto_approve 的存在 |
| 补偿任务需要额外的 FEISHU_FOLDER_INGEST 标记锁来隔离 | 治标不治本 |

### 1.2 重构目标

**让 `DocumentPipeline` 成为唯一的文档状态机编排器。**

- 所有状态转换在一处集中管控
- 外部调用方（API、扫描服务、补偿任务）只提交任务，不关心内部状态
- 删除死代码，职责分离

## 2. 状态机

```
                         ┌──────────────────┐
                         │  PENDING_EXTRACT  │
                         └────────┬─────────┘
                                  │ pipeline.extract(doc_id)
                         ┌────────▼─────────┐
                         │    EXTRACTED      │ (瞬态，立即跳转)
                         └────────┬─────────┘
                                  │
                         ┌────────▼─────────┐
                  ┌──────│  PENDING_REVIEW   │──────┐
                  │      └────────┬─────────┘      │
                  │               │                 │
          pipeline.approve()      │        pipeline.reject()
                  │               │                 │
           ┌──────▼──────┐ ┌──────▼──────┐  ┌──────▼──────┐
           │   APPROVED   │ │   SLICING    │  │  REJECTED    │
           └──────┬──────┘ └──────┬──────┘  └─────────────┘
                  │               │
           ┌──────▼──────┐        │
           │  VECTORIZING │◄───────┘
           └──────┬──────┘
                  │
           ┌──────▼──────┐
           │  COMPLETED   │
           └─────────────┘
                  │
            任一阶段失败
                  │
           ┌──────▼──────┐
           │   FAILED     │──→ pipeline.retry() 回到对应阶段
           └─────────────┘
```

### 状态说明

| 状态 | 含义 | 触发方 |
|------|------|--------|
| `PENDING_EXTRACT` | 等待提取 | 文档创建后 |
| `EXTRACTED` | 提取完成（瞬态） | `pipeline.extract()` |
| `PENDING_REVIEW` | 等待审核 | 提取完成后 |
| `APPROVED` | 审核通过 | `pipeline.approve()` |
| `SLICING` | 切片中（合同类） | `pipeline.approve()` 内部 |
| `VECTORIZING` | 向量化中 | `pipeline.approve()` 内部 |
| `COMPLETED` | 处理完成 | 向量化成功 |
| `REJECTED` | 已驳回 | `pipeline.reject()` |
| `FAILED` | 处理失败 | 任一步骤异常 |

## 3. Pipeline 对外接口

```python
class DocumentPipeline:
    """文档处理状态机编排器。所有状态转换的唯一入口。"""

    async def extract(self, doc_id: int) -> None:
        """提取内容 → PENDING_REVIEW
        入口状态: PENDING_EXTRACT
        出口状态: PENDING_REVIEW | FAILED
        """

    async def approve(self, doc_id: int, reviewer_id: int | None = None) -> None:
        """审核通过 → 切片 → 向量化 → COMPLETED
        入口状态: PENDING_REVIEW
        出口状态: COMPLETED | FAILED
        reviewer_id=None 表示系统自动通过（不生成 Review 记录）
        """

    async def reject(self, doc_id: int, reviewer_id: int, comment: str) -> None:
        """驳回 → REJECTED
        入口状态: PENDING_REVIEW
        出口状态: REJECTED
        """

    async def retry(self, doc_id: int) -> None:
        """重试失败文档
        入口状态: FAILED | REJECTED
        有 content → 跳过提取，直接 approve
        无 content → extract
        """

    async def resubmit(self, doc_id: int, content: str) -> None:
        """编辑内容后重新提审
        入口状态: REJECTED
        出口状态: PENDING_REVIEW
        """
```

## 4. 流程一：用户上传

### 4.1 创建文档 → 提取

```
POST /api/v1/documents/create
  │
  ├─ 创建 Document(status=PENDING_EXTRACT, uploader_id=user_id)
  └─ BackgroundTasks → pipeline.extract(doc_id)
```

**`pipeline.extract` 内部流程：**

```
pipeline.extract(doc_id)
  │
  ├─ Redis 锁 DOCUMENT_PROCESS:{doc_id} (TTL=1800s)
  │   └─ 已锁定 → 跳过
  │
  ├─ run_extraction(doc) → 按 doc_type_code 路由提取器
  │   ├─ contract:  _fetch_file_bytes → document_converter → Vision LLM → markdown
  │   ├─ ppt:       _fetch_file_bytes → document_converter → Vision LLM → markdown
  │   └─ feishu_doc: 飞书 API 拉 JSON → agent 转 markdown
  │
  ├─ 成功:
  │   ├─ doc.content = result.content
  │   ├─ doc.source_meta 合并 result.source_meta_patch
  │   ├─ doc.status: EXTRACTED → PENDING_REVIEW
  │   └─ 释放锁
  │
  └─ 失败:
      ├─ doc.status = FAILED
      ├─ doc.error_message = str(e)
      └─ 释放锁
```

### 4.2 审核通过

```
POST /api/v1/reviews/approve
  │
  └─ BackgroundTasks → pipeline.approve(doc_id, reviewer_id=user_id)
```

**`pipeline.approve` 内部流程：**

```
pipeline.approve(doc_id, reviewer_id=user_id)
  │
  ├─ 校验: doc.status == PENDING_REVIEW
  │
  ├─ 创建 Review 记录 (reviewer_id, action=APPROVE, comment)
  ├─ doc.status = APPROVED
  │
  ├─ Redis 锁 DOCUMENT_VECTORIZE:{doc_id} (TTL=1800s)
  │   └─ 已锁定 → 跳过
  │
  ├─ 清理旧向量数据 (chunk_service.delete_by_doc_id)
  │
  ├─ 按 doc_type_code 路由:
  │   ├─ contract:
  │   │   ├─ _finalize_content_from_review (从 DocumentPage 拼最终原文)
  │   │   ├─ 已注册切片处理器 → _run_slicing → SLICING
  │   │   ├─ VECTORIZING
  │   │   └─ _vectorize_contract (逐条款向量化 + 写 summary)
  │   │
  │   ├─ 分页类型 (is_paged_type):
  │   │   ├─ VECTORIZING
  │   │   └─ _vectorize_from_pages (逐页向量化)
  │   │
  │   └─ 其他:
  │       ├─ VECTORIZING
  │       └─ rag_service.ingest_document (整文向量化)
  │
  ├─ 成功: doc.status = COMPLETED
  │
  └─ 失败:
      ├─ doc.status = FAILED
      ├─ doc.error_message = str(e)
      └─ 释放锁
```

### 4.3 驳回

```
POST /api/v1/reviews/reject
  │
  └─ pipeline.reject(doc_id, reviewer_id, comment)
       ├─ 校验: doc.status == PENDING_REVIEW
       ├─ 创建 Review 记录 (reviewer_id, action=REJECT, comment)
       └─ doc.status = REJECTED
```

### 4.4 重试

```
POST /api/v1/documents/retry
  │
  └─ BackgroundTasks → pipeline.retry(doc_id)
       ├─ 校验: doc.status in (FAILED, REJECTED)
       ├─ 有 content + FAILED → pipeline.approve(doc_id)   # 补偿向量化失败
       └─ 无 content / REJECTED → pipeline.extract(doc_id)  # 重新提取
```

### 4.5 编辑内容后重新提审

```
POST /api/v1/documents/update_content
  │
  └─ pipeline.resubmit(doc_id, content)
       ├─ 校验: doc.status == REJECTED
       ├─ doc.content = content
       └─ doc.status = PENDING_REVIEW
```

## 5. 流程二：文件夹监听（自动）

### 5.1 扫描入口

```
scheduler → scan_all()
  │
  ├─ 查所有 active + 未删除的 watch
  ├─ 按 scan_interval 判断是否到期
  └─ asyncio.gather → 每个 watch 独立 scan_one
```

### 5.2 单 watch 扫描

```
scan_one(watch)
  │
  ├─ Redis 锁 FEISHU_FOLDER_SCAN:{watch_id} (TTL=600s)
  │
  ├─ 拉飞书文件夹文件列表 (分页，上限 FEISHU_FOLDER_SCAN_MAX_FILES_PER_FOLDER)
  │
  ├─ 对比 FeishuFolderFile 表 → 得出:
  │   ├─ new_files      (file_token 不在表中)
  │   ├─ updated_files  (modified_time 更新)
  │   └─ deleted_files  (飞书侧已删除)
  │
  ├─ _ingest_new_files(watch, new_files)
  ├─ _re_ingest_updated_files(watch, updated_files)
  ├─ _mark_deleted_files(watch, deleted_files)
  │
  └─ 释放锁，更新 watch.last_scan_status
```

### 5.3 新文件入库

```
_ingest_new_files(watch, new_files)
  │
  ├─ 截断: batch_limit = FEISHU_FOLDER_SCAN_BATCH_LIMIT (默认 50)
  │
  └─ for each file in batch:
       └─ _ingest_one(watch, file_meta)
            │
            ├─ FeishuFolderFile.update_or_create(ingest_status=pending)
            ├─ 类型预检 → 不支持则 skipped
            ├─ Document.create(PENDING_EXTRACT, uploader_id=0)
            ├─ FeishuFolderFile → document_id=doc.id, ingest_status=ingested
            ├─ Redis 标记锁 FEISHU_FOLDER_INGEST:{doc_id} (TTL=3600s)
            │
            └─ asyncio.create_task(_do_process(watch, doc_id))
```

### 5.4 文档处理（自动）

```
_do_process(watch, doc_id)
  │
  ├─ async with _process_sem (FEISHU_FOLDER_PROCESS_CONCURRENCY, 默认 3)
  │
  └─ try:
  │     ├─ pipeline.extract(doc_id)
  │     │
  │     └─ if watch.auto_approve:
  │           pipeline.approve(doc_id)   # reviewer_id=None，不创建 Review 记录
  │        else:
  │           等待人工审核
  │
  └─ finally:
       _release_ingest_lock(doc_id)  # 释放标记锁
```

### 5.5 变更文件重新入库

```
_re_ingest_updated_files(watch, updated_files)
  │
  └─ for each file in batch:
       └─ _re_ingest_one(watch, file_meta)
            │
            ├─ 查 FeishuFolderFile → 获取旧 document_id
            ├─ 清理旧向量 (chunk_service.delete_by_doc_id)
            ├─ 清理旧切片 (SlicingResult.delete)
            ├─ 清理旧页面 (DocumentPage.delete + 截图文件)
            ├─ 旧 Document 软删除 (is_deleted=True)
            │
            ├─ 重置 FeishuFolderFile (ingest_status=pending, document_id=None)
            ├─ 创建新 Document(PENDING_EXTRACT)
            ├─ 更新 FeishuFolderFile
            ├─ 设置 FEISHU_FOLDER_INGEST 标记锁
            │
            └─ asyncio.create_task(_do_process(watch, doc_id))
```

## 6. 补偿任务

```
scheduler (每 N 分钟)
  │
  ├─ compensate_pending_extract()
  │   ├─ 查 PENDING_EXTRACT + is_deleted=False
  │   ├─ 并行检查 FEISHU_FOLDER_INGEST 标记 → 过滤托管中的文档
  │   ├─ Semaphore(COMPENSATE_CONCURRENCY, 默认 5)
  │   └─ asyncio.gather → pipeline.extract(doc_id)
  │
  ├─ compensate_approved()
  │   ├─ 查 APPROVED + is_deleted=False
  │   ├─ 并行检查 FEISHU_FOLDER_INGEST 标记 → 过滤托管中的文档
  │   ├─ Semaphore(COMPENSATE_CONCURRENCY, 默认 5)
  │   └─ asyncio.gather → pipeline.approve(doc_id)
  │
  └─ reset_stuck_documents()
      ├─ 查 SLICING/VECTORIZING + updated_at 超过阈值
      ├─ 检查向量化锁是否还在 → 还在则跳过（任务真在跑）
      └─ 重置为 APPROVED → 下一轮 compensate_approved 自动补偿
```

## 7. 并发控制

### 7.1 文档级互斥锁（Redis）

| 锁 Key | 用途 | TTL |
|--------|------|-----|
| `DOCUMENT_PROCESS:{doc_id}` | 防止同一文档被并发提取 | 1800s |
| `DOCUMENT_VECTORIZE:{doc_id}` | 防止同一文档被并发向量化 | 1800s |
| `FEISHU_FOLDER_INGEST:{doc_id}` | 标记文档由飞书托管，补偿任务跳过 | 3600s |

### 7.2 全局并发信号量

| 配置项 | 默认值 | 作用范围 |
|--------|--------|---------|
| `FEISHU_FOLDER_PROCESS_CONCURRENCY` | 3 | 飞书扫描触发的文档处理任务数 |
| `COMPENSATE_CONCURRENCY` | 5 | 补偿任务并发数 |
| `VISION_LLM_CONCURRENCY` | 2 | 全局 VLM 调用并发上限（所有来源共享） |

### 7.3 飞书 API 连接池

`FeishuService` 复用 `httpx.AsyncClient` 连接池：
- `timeout=30s, connect=15s`
- `max_connections=20, max_keepalive_connections=10`
